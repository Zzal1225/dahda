# 체험 계정의 실제 문자 받아 보기

날짜: 2026-11-05

## 배경

채용 담당자가 외부 API 연동을 자기 폰으로 확인할 수 있어야 한다. 지금까지 체험 계정은 항상 가짜 발송기였고, 실제 발송은 허용 번호로만 나갔다.

## 결정

체험 계정에 한 경로만 연다. 입력한 번호로 고정 문구 1건을 솔라피로 보낸다.

| 안전장치 | 위치 |
| --- | --- |
| 본문 고정, 입력 불가 | 서버 상수 `DEMO_SMS_BODY`. 보내기 직전 `allowDemoRequest`가 다시 대조 |
| 발신번호 고정 | `DEMO_SENDER_NUMBER`. 앱과 워커의 값이 다르면 나가지 않음 |
| 체험 계정당 1건, 번호당 1건 | `demo_sends` 유일 제약 |
| 전체 하루 10건 | `reserve_real_sends`. 일반 실제 발송과 같은 카운터 |
| 잔액 소진 시 중단 | 체험 잔액은 `reserve_balance`, 업체 잔액은 솔라피 거절 |
| 재발송 불가 | `retry_targets`에서 제외 |
| CI·테스트 | `SMS_PROVIDER`가 `solapi`가 아니면 플래그가 있어도 가짜 |

## 버린 대안

- **공개 ID/PW 계정**: Supabase에서는 로그인한 사용자가 자기 비밀번호를 바꿀 수 있어 공유 계정을 잠글 수 있다. 다음 방문자가 앞사람의 전화번호도 보게 된다. 체험 계정은 방문자마다 조직이 달라 두 문제가 없다.
- **허용 목록만 유지**: 안전하지만 담당자가 자기 폰으로 확인할 수 없다.
- **인증 문자로 번호 주인 확인**: 인증 문자도 그 번호로 나가는 문자라 위험이 줄지 않는다.

## 남은 위험

- **번호 주인을 확인하지 못한다.** 동의 체크는 입력자의 진술일 뿐이다. 다른 사람 번호를 넣으면 고정 문구 1건이 그 사람에게 간다. 본문 고정과 번호당 1건으로 피해를 1건으로 제한한다.
- **익명 계정은 다시 만들 수 있다.** 체험 계정당 제한은 쉽게 우회된다. 실제 한도는 번호당 1건과 전체 하루 10건이다. 하루 10건을 소진하면 그날은 사용자 본인의 실제 발송 시험도 막힌다.
- **받는 사람에게 사용자의 발신번호가 보인다.** 등록된 발신번호라 숨길 수 없다.
- **API 키의 IP 제한을 풀어야 한다.** Edge Function에서 나가는 IP가 키의 허용 목록에 없으면 `SOLAPI_Forbidden`으로 거절된다(2026-11-05 운영 로그: "허용되지 않은 IP"). 제한을 풀면 키가 유출됐을 때 위 안전장치가 적용되지 않으므로 업체 잔액을 소액만 둔다.

## 확인 필요

- 이 문자가 정보통신망법의 영리목적 광고성 정보에 해당하지 않는다는 판단은 공식 해석을 확인하지 않았다. 혜택·가격·방문 유도를 넣지 않았고 수신자가 직접 요청한 문자라 광고 표기를 넣지 않았다. 운영 전 확인이 필요하다.
- 솔라피 약관상 이런 시연 발송이 허용되는지 확인하지 않았다.
- Edge Function이 고정 IP를 보장하지 않는다는 점은 공식 문서로 다시 확인하지 않았다.
- 개인정보: 번호는 체험 조직과 함께 3일 뒤 삭제된다. `demo_sends`의 해시는 되돌릴 수 있는 값이라 익명화가 아니며 30일 뒤 삭제한다. 웹훅 원문에도 번호가 있을 수 있고 90일 보관이다. 화면 안내 문구에는 이 웹훅 보관을 아직 적지 않았다.
