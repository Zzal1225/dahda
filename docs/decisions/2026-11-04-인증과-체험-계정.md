# 인증과 체험 계정

2026-11-04 · 출처: 설치된 `next@16.4.5`의 `02-guides/authentication-with-cache-components.md`, `01-getting-started/16-proxy.md`, `@supabase/ssr@0.12.7` 타입 정의

## 결정

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 세션 쿠키 | `@supabase/ssr` 추가(사용자 승인) | 토큰 갱신과 쿠키 분할을 직접 구현하지 않는다 |
| 현재 사용자 조회 | `getUser` + `members` 조회, react `cache`만 사용 | `use cache: private`는 역할 전환 직후 이전 역할이 최대 5분 보일 수 있다 |
| 렌더링 시점 | `connection()`으로 실제 요청까지 대기 | Auth 클라이언트가 생성 시 현재 시각을 읽어 미리 렌더링에서 거부된다 |
| Proxy의 역할 | 토큰 갱신과 세션 없는 요청의 이동만 | 문서가 권한 판단 용도로 권하지 않고, 소속 판단까지 넣으면 리디렉션이 순환한다 |
| 체험 본사 | 사용자마다 생성, 3일 뒤 pg_cron 삭제 | 공유하면 한 사람의 변경이 다른 사람 화면에 보인다 |
| 역할 전환 메뉴 | 본사 + 지점 전체 | 시안은 본사·성수점 2개지만, 지점 이름이 바뀌어도 동작하고 지점 간 분리를 보여 줄 수 있다 |
| shadcn/ui | CLI 대신 필요한 부품만 복사해 토큰에 직접 연결 | CLI가 `globals.css`를 다시 쓰고, 변수 이름을 한 번 더 연결할 이유가 없다 |
| 로그아웃 위치 | 아바타 메뉴 | 시안은 설정 화면에 두지만 설정 화면은 나중에 만든다 |

## 미룬 것

- 체험 샘플의 주소록·발송 내역: 해당 화면을 만들 때 `create_trial_org`에 추가한다.
- 본사 지점 선택 드롭다운: 그 기준으로 바뀌는 숫자가 생기는 첫 화면 작업(step5)에서 넣는다.
- 모바일 승인함 예외: 승인함을 만드는 step3에서 처리한다.

## 배포 시 주의 (1-7)

`supabase/config.toml`의 `enable_anonymous_sign_ins`는 로컬 설정이다. 클라우드 프로젝트에서는 익명 로그인을 따로 켜야 하고, pg_cron 확장과 `delete-expired-trials` 작업이 등록되었는지 확인한다. 익명 로그인 횟수 제한(로컬 기본값 시간당 30회)도 공개 체험 기준으로 다시 정한다.
