# 광고 수신 동의

날짜: 2026-11-05.

## 문제

작성 화면에 "동의를 받은 번호에만 보낼 수 있어요"라는 안내만 있었다. 저장된 값이 없어 코드가 막을 수 없었다. 수신거부 제외와 사전 동의는 다른 규칙이다.

## 결정

- `contacts.consent_at`: 값이 있으면 동의 시각, 없으면 기록 없음. 기본값이 없다.
- 광고는 `consent_at`이 없는 번호를 서버에서 제외한다. 화면 미리보기와 접수가 같은 함수(`resolveRecipients`)를 써서 숫자가 같다.
- 일반 문자는 동의를 보지 않는다.
- 같은 번호가 여러 지점에 있으면 하나라도 미동의일 때 제외한다. 동의가 지점별 기록이라, 한 지점의 동의를 다른 지점의 광고에 쓰지 않는 좁은 쪽을 택했다.
- 업로드 칸은 Y, N, 날짜를 받는다. 모르는 값은 미동의로 넘기지 않고 오류로 보여 준다. 비어 있으면 미동의다.
- 기존 번호는 미동의로 시작한다. 동의 기록이 없는 번호에 광고를 보내는 것보다 빠지는 쪽이 안전하다.

## 범위 밖

동의 수집 화면, 철회와 이력 관리, 동의 유지 확인(법의 2년 주기 안내)은 하지 않는다. 콘솔은 저장된 값으로 제외만 한다. 승인 대기 중이나 예약 중에 동의가 바뀌어도 접수 때 계산한 수신자가 그대로 나간다.

## 확인 필요

법 조항의 적용과 표기는 법률 검토를 받지 않았다. 규칙의 출처는 광고 규칙 결정 기록을 따른다.
