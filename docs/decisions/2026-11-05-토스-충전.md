# 토스 충전

날짜: 2026-11-05. 출처는 모두 이날 읽은 토스페이먼츠 공식 문서다.

## 문서에서 확인한 것

| 항목 | 내용 | 출처 |
| --- | --- | --- |
| 키 종류 | 결제창(구버전)은 API 개별 연동 키 `test_ck`, `test_sk`. 주문서형·결제창형은 `test_gck`, `test_gsk` | [SDK](https://docs.tosspayments.com/sdk/v2/js), [API 키](https://docs.tosspayments.com/reference/using-api/api-keys) |
| 테스트 결제 | 테스트 키는 승인이 가상으로 이뤄지고 금액이 차감되지 않는다 | API 키 |
| 승인 | `POST /v1/payments/confirm`, 시크릿 키 Basic 인증. 인증 후 10분 안에 호출 | [코어 API](https://docs.tosspayments.com/reference) |
| 금액 대조 | 돌아온 `amount`가 요청 금액과 같은지 확인한 뒤 승인 | [SDK 결제창](https://docs.tosspayments.com/sdk/v2/js/payment) |
| 멱등 키 | POST에 `Idempotency-Key`, 15일 유효, 같은 요청에 첫 응답 반환 | [인증](https://docs.tosspayments.com/reference/using-api/authorization) |
| 조회 | `GET /v1/payments/{paymentKey}` | 코어 API |
| 웹훅 | `PAYMENT_STATUS_CHANGED`, 10초 안에 200, 최대 7회 재전송 | [웹훅](https://docs.tosspayments.com/guides/v2/webhook) |
| 웹훅 서명 | `tosspayments-webhook-signature`, 본문과 전송 시각의 HMAC-SHA256. 보안 키는 API 개별 연동 키에만 발급 | [웹훅 이벤트](https://docs.tosspayments.com/reference/using-api/webhook-events) |

## 결정

**결제위젯 대신 결제창.** 기획서는 결제위젯이었다. 개발자센터에 `test_gck`와 `test_ck`가 모두 있었고, 문서상 웹훅 서명용 보안 키가 API 개별 연동 키에만 발급되어 결제창을 골랐다. 대신 결제 UI가 화면에 내장되지 않는다. 문서는 이 제품을 "구버전"으로 부르고 새 연동에는 주문서형을 권한다. 그래도 금액 대조, 승인, 멱등, 웹훅 처리는 같고, 바꿀 때 고칠 곳은 주로 `charge-panel.tsx`와 키 세트다.

**웹훅 본문을 믿지 않는다.** 웹훅이 오면 결제 키만 꺼내 조회 API로 상태와 금액을 다시 읽는다. 서명은 있으면 검사하고 틀리면 401로 거부하지만, 없으면 처리를 계속한다. 충전 여부는 토스에 실제로 승인됐는지로만 정해지므로 위조 요청으로는 충전되지 않는다.

**모르면 실패로 확정하지 않는다.** 타임아웃과 5xx는 승인됐는지 알 수 없다. 조회로 확인하고, 그래도 모르면 대기로 안내해 다시 결제하지 않게 한다. 이후 웹훅이 마무리한다.

**failed에서 done으로 갈 수 있다.** 다른 상태와 달리 역행을 허용하는 예외다. 토스가 승인했다면 돈이 실제로 나간 것이고, 막으면 충전이 사라진다. `canceled`만 최종 상태다.

**계정은 세션에서만 읽는다.** 시작과 승인 모두 입력으로 계정을 받지 않는다. 본사 화면도 지점 계정에는 충전 버튼이 없다.

**금액은 버튼 네 개.** 1만, 3만, 5만, 10만 원. 체험 계정도 충전할 수 있다. 테스트 결제라 출금이 없고, 담당자가 결제 흐름을 직접 볼 수 있다.

**라이브 키를 코드로 거부한다.** `test_ck_`, `test_sk_`로 시작하지 않으면 키가 없는 것으로 처리한다.

**범위 밖.** 가상계좌(입금 대기 흐름 필요), 결제 취소와 환불 화면. 토스 쪽에서 취소된 결제는 웹훅으로 잔액을 줄이지 않는다. 충전금을 이미 쓴 경우의 처리를 정해야 해서 미뤘다.

## 실제 시험 (2026-11-05)

운영에서 체험 계정으로 테스트 키 카드 결제 1건(1만 원)을 진행했다.

| 항목 | 결과 |
| --- | --- |
| 승인 | 결제창에서 돌아와 `done`, 결제 키와 승인 시각 저장 |
| 거래 기록 | `charge` 1건, 1만 원. 잔액 증가는 화면에서 확인 |
| 웹훅 | 승인 약 4초 뒤 도착, `applied`. 앞서 충전한 결제라 거래 기록은 그대로 1건 |
| 서명 | `PAYMENT_STATUS_CHANGED`에도 서명 헤더가 왔고 보안 키로 검증을 통과했다 |

## 확인하지 못한 것

- 카카오페이 같은 간편결제. 테스트 결제 중 앱에 출금 안내가 떠서 승인하지 않고 카드로 진행했다. 문서가 명시한 예시는 카드 번호와 휴대폰 번호뿐이라, 간편결제 앱이 어떻게 처리하는지는 모른다.
- 실제 카드 명세서. 문자 알림이 없었고 문서상 차감되지 않지만, 명세서로 확인한 것은 아니다.
- 승인 거절, 타임아웃, 웹훅이 리다이렉트보다 먼저 오는 경우. 단위·통합 테스트로만 확인했다.
