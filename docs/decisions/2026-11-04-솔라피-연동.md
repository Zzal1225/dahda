# 솔라피 연동

날짜: 2026-11-04. 출처는 모두 이날 읽은 공식 문서와 SDK `solapi@6.0.1`의 타입·소스다.

## 확인한 것

| 항목 | 내용 | 출처 |
| --- | --- | --- |
| 호출 제한 | 발송 API 5초에 100회(베이직), 초과 시 429 | [rateLimit](https://solapi.com/developers/api/rateLimit), [pricing](https://solapi.com/pricing) |
| 호출당 건수 | 최대 10,000건 | SDK `MessageService.send` 주석 |
| 인증 | `HMAC-SHA256 apiKey, date, salt, signature` | SDK 소스. [webhook](https://solapi.com/developers/api/webhook)의 등록 예시는 Bearer로 적혀 있어 문서끼리 다르다 |
| 웹훅 형식 | JSON 배열, 한 요청에 여러 건, `X-Solapi-Event-Name` | webhook |
| 웹훅 재시도 | 200번대가 아니거나 5초 초과 시 8회, 15분부터 2배. 모두 실패하면 비활성화 | webhook |
| 웹훅 검증 | `X-Solapi-Secret`에 비밀값의 SHA1 | webhook |
| 도착 코드 | 4000 수신 완료, 2000·3000은 진행 중 | [msgstatus](https://solapi.com/developers/api/msgstatus) |
| 단가 | SMS 18원, LMS 45원, VAT 별도 | pricing. 우리 단가 20원·50원은 VAT 포함 19.8원·49.5원보다 높다 |

## 결정

**묶음 500건.** 측정 3에서 10초마다 한 묶음이면 100건은 1만 건에 약 17분, 500건은 약 3분이었다. 호출당 1만 건, 5초 100회 제한에 닿지 않는다.

**우리 키는 `customFields`로 보낸다.** 응답과 웹훅에 그대로 돌아오는 필드다.

**응답에서 찾지 못한 건은 재시도하지 않는다.** 접수됐을 수 있다. 실제 문자는 중복 발송이 환불보다 나쁘다.

**하루 상한은 보내기 전에 DB에서 예약한다.** 메시지 행을 세면 동시 워커나 저장 전 중단을 놓친다. 재시도도 상한을 쓴다.

**안전장치는 닫힌 쪽으로 고장 난다.** 허용 번호가 비면 아무에게도 보내지 않고, 상한을 확인하지 못해도 보내지 않는다.

**SDK 오류를 나눈다.** 4xx는 인증, 미등록 발신번호, 잔액처럼 다시 보내도 같으므로 재시도하지 않고 업체 코드를 실패 사유로 남긴다. 429만 재시도한다. 200을 받고 해석하지 못하면 접수됐을 수 있어 재시도하지 않는다. 처음에는 전부 재시도로 묶어, 키가 틀렸는데도 "대기"로 남고 원인이 보이지 않았다.

## 알려진 위험

**멱등 키가 없다.** 문서와 SDK 어디에도 없다. 그래서 다음 두 경우 같은 문자가 두 번 갈 수 있다.

- 업체는 접수했는데 응답이 끊겨 네트워크 오류로 재시도할 때
- 접수 뒤 결과 저장 전에 워커가 죽어 임대가 끝난 뒤 다시 보낼 때

기획서대로 네트워크 오류는 재시도한다. 막으려면 재시도 전에 `customFields`로 조회해야 하는데, 조회 API가 그 조건을 지원하는지 확인하지 못했고 2차로 미룬다. 지금은 허용 번호와 하루 상한이 피해 범위를 막는다.

**웹훅 검증이 약하다.** 비밀값의 고정 해시라 본문 위조와 재전송을 막지 못한다. 재전송은 상태 전이가 무시한다. 값이 새면 결과를 위조해 실패분을 환불받을 수 있으므로 HTTPS 주소만 등록한다. 발신 IP 목록은 문서에서 찾지 못했다.

**웹훅 5초 제한.** 건마다 DB를 왕복하므로 큰 배열은 넘길 수 있다. 넘으면 15분 뒤 재전송되고 중복은 무시된다. 8회 연속 실패하면 비활성화되므로 대량 발송 전에 묶음 처리가 필요하다.

## 확인하지 못한 것

- 실제 응답에 `customFields`가 돌아오는지(타입에는 있다). 실제 1건 발송으로 확인한다. 돌아오지 않으면 모든 건이 `SOLAPI_NO_RESULT`가 된다.
- 개인 발신번호 등록 절차, 체험 크레딧, 테스트 모드: 문서에서 찾지 못했다.
- 코드의 영구·일시 구분: 문서가 나누지 않아 설명을 보고 정했다. 코드에 `확인 필요`로 표시했다.
- 무료 수신거부 080 번호: 아직 설정값이다.
