# 테스트는 모두 통과했는데 실제 문자가 화면에 반영되지 않았다

## 문제

자동 테스트와 가짜 발송기로는 전체 흐름이 통과했다. 그런데 운영에서 실제 문자를 보내자 차례로 세 가지 문제가 나타났다.

1. 문자가 나가지 않았다(`SOLAPI_Forbidden`).
2. 문자는 폰에 왔지만 화면은 계속 "확인 중"이었다.
3. 고치는 도중 발송이 다시 실패했다(`SOLAPI_SignatureDoesNotMatch`).

## 원인

1. **API 키의 IP 제한.** Edge Function의 주소가 허용 목록에 없었다. 로그의 업체 메시지로 확인했다.
2. **secret 없이 등록된 웹훅.** 처음에는 서버의 비밀값이 업체와 다르다고 추정했는데 틀렸다. 콘솔의 수정 화면에는 secret 칸이 없었고, 조회 API로 보니 웹훅의 secret이 비어 있었다. 업체는 secret이 있을 때만 서명 헤더를 보내므로 서버가 모두 거부했다.
3. **비슷한 이름의 비밀값.** 웹훅 값을 바꾸려다 API Secret을 재생성했다. 발송 서명은 예전 값으로 만들어지고 있었다.

## 해결

- API 키의 IP 범위를 열고, 키가 유출될 경우의 피해를 줄이려고 업체 잔액을 적게 유지했다.
- 재생성한 API Secret을 Edge Function에 다시 등록했다.
- 콘솔로 할 수 없어 API로 secret이 있는 웹훅을 등록하는 `scripts/solapi-webhook.mjs`를 만들었다. 조회 응답의 비밀값은 출력하지 않고 있음 여부만 보여 준다.
- 서버 값을 맞추고 옛 웹훅을 지웠다.

## 결과

접수, 폰 도착, 서명 검증된 웹훅, 도착 표시, 완료, 금액 확정까지 운영에서 확인했다.

## 배운 것

- 값이 "있다"와 "같다"는 다르고, 상대가 값을 보내는지는 또 다른 문제다. 조회 API를 먼저 썼으면 추정을 건너뛸 수 있었다.
- 실패 코드와 웹훅 수신 기록을 남긴 덕분에, 문제가 발송 단계인지 결과 단계인지 코드를 보지 않고 가를 수 있었다.
- 웹훅 기록에 서명 헤더의 유무가 없어 원인을 한 번에 가리지 못했다. 앞으로는 "틀림"과 "없음"을 나눠 기록한다. 토스 웹훅 검증은 이렇게 만들었다.
