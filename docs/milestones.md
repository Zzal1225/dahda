# 마일스톤

## step1 (2026-11-04)

체험 로그인 후 역할을 바꾸면 메뉴와 범위가 달라지고, 배포 주소에서 동작한다.

배포 주소: https://dahda-xi.vercel.app

| 항목 | 결과 |
| --- | --- |
| 단위 테스트 | 223개 |
| 통합 테스트 (실제 Supabase) | 137개 |
| 브라우저 테스트 (Playwright, 프로덕션 빌드) | 11개 |
| CI | GitHub Actions에서 위 테스트와 lint, typecheck, 빌드 실행 |
| Lighthouse | 측정 대상인 발송 내역 화면이 없어 step2 이후 |

### 배포 환경에서 확인한 것

체험 시작, 본사 잔액 표시, 지점 관리 조회, 지점 역할 전환 후 메뉴 제거와 주소 직접 입력 차단, 새로고침 후 역할 유지, 로그아웃. 비로그인 사용자의 테이블·함수 접근 차단. 운영 DB의 테이블·함수 권한이 로컬과 같은지 비교(다른 점은 automatic RLS 함수 하나).

### 배포 환경에서 확인하지 못한 것

- 이메일 로그인 성공: 운영 DB에 실제 계정을 아직 만들지 않았다.
- 체험 데이터 자동 삭제의 실제 실행: 예약은 등록되었고, 첫 삭제 대상은 3일 뒤 만료된다.
- 동시 사용 부하: 측정하지 않았다.

## step2 (2026-11-04)

발송 내역에서 10만 행이 매끄럽게 스크롤되고 새로고침해도 필터와 위치가 유지된다.

| 항목 | 결과 |
| --- | --- |
| 단위 테스트 | 319개 |
| 통합 테스트 | 154개 |
| 브라우저 테스트 | 17개 |
| 측정 1 | 접속부터 표시까지 12,391ms → 679ms, 스크롤 6fps → 60fps ([기록](performance.md)) |

범위 밖으로 미룬 것: 실패 건 재발송과 엑셀 내보내기 버튼은 기능이 없어 숨겼다(재발송은 step4, 내보내기는 SheetJS를 들이는 step3 이후). 실시간 갱신 표시는 step4. 발송 건 목록은 최근 200건까지만 보여 주며 넘치면 안내한다.

## step3 (2026-11-04)

엑셀로 주소록을 올리고, 광고 규칙이 적용된 문자를 작성하고, 지점 광고를 본사가 승인한다. 실제 발송은 step4다.

| 항목 | 결과 |
| --- | --- |
| 단위 테스트 | 493개 |
| 통합 테스트 | 199개 |
| 브라우저 테스트 | 48개 |
| 측정 2 | 10만 행 엑셀 파싱 중 입력 반응 ([기록](performance.md)) |

범위 밖으로 미룬 것: 본사 엑셀 내보내기는 아직 없어 버튼을 숨겼다. 수신 동의 관리는 범위 밖이다. 수신거부 080 번호는 설정값이며 실제 번호를 정하지 않았다. 모바일 화면은 Chromium의 375px로만 확인했고 Safari(WebKit)와 실제 기기는 확인하지 않았다.

### step3 배포 환경에서 확인한 것

체험 계정으로 광고 승인 요청, 사이드바 대기 건수, 승인 후 지점 잔액 차감, 사유 반려와 지점의 사유 확인, 승인 건의 취소 버튼 없음, 예약 취소 후 환불(새로고침으로도 확인), 375px에서 승인함만 표시.

알려진 문제: 예약 취소 후 상단 잔액이 배포 환경에서 약 6초 뒤에 갱신됐다. 환불 자체는 즉시 맞다. 원인은 아직 확인하지 않았다.

## step4 (2026-11-05)

발송 큐, 실제 문자, 결과 웹훅, 실시간 반영, 재발송, 체험 실제 문자, 토스 테스트 충전이 운영에서 동작한다.

| 항목 | 결과 |
| --- | --- |
| 단위 테스트 | 659개 |
| 통합 테스트 | 269개 |
| 브라우저 테스트 | 64개 |
| 측정 3 | 1만 건 처리, 초당 접수 71건 → 2,455건 ([기록](performance.md)) |
| 측정 4 | 웹훅 반영 중앙값 5,164ms → 274ms |
| 추가 측정 | 함수 리전 이동 후 화면 응답 1.4~2.1초 → 0.4~0.5초 |

### 운영에서 확인한 것

- 실제 문자: 접수, 폰 도착, 서명된 웹훅, 도착 표시, 완료. 실패 건은 "발송 실패"로 표시되고 금액이 환불됐다.
- 체험 문자: 자기 번호로 고정 문구 1건 수신, 화면이 도착으로 바뀜.
- 토스 충전: 카드 테스트 결제 1건, 잔액 증가, 거래 기록 1건, 서명 검증된 웹훅.

### 알려진 문제와 범위 밖

- 웹훅이 끝내 오지 않은 메시지는 계속 "확인중"이고 금액도 확정되지 않는다. 정리하는 작업이 아직 없다. 시험 중 생긴 1건이 운영에 남아 있다.
- 실패 코드 웹훅, 여러 건이 묶인 웹훅은 실제로 받아 보지 않았다.
- 토스 쪽 결제 취소는 잔액에 반영하지 않는다. 가상계좌와 간편결제는 확인하지 않았다.
- 솔라피 API 키의 IP 제한을 열어 두었다. Edge Function 주소가 고정이 아니어서 잔액을 적게 유지하는 것으로 대신한다.
