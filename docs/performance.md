# 성능 측정

직접 잰 숫자만 적는다. 측정 조건이 다르면 비교하지 않는다.

## 측정 1: 10만 행 발송 내역 표

**스크립트**: `scripts/measure-table.mjs`

**조건**

| 항목 | 값 |
| --- | --- |
| 기기 | AMD Ryzen 5 5600X, RAM 16GB, Windows 10 |
| 브라우저 | Playwright Chromium Headless Shell, 1280×800 |
| 서버 | 같은 PC의 `next start`(프로덕션 빌드)와 로컬 Supabase |
| 데이터 | `npm run db:seed:large`의 메시지 100,000행 |
| 횟수 | 3회 실행의 중앙값 |
| 스크롤 | 5초 동안 맨 위에서 맨 아래까지 일정 속도 |

헤드리스 환경이고 서버와 브라우저가 같은 PC라 실제 사용자 수치가 아니다. 같은 조건의 전후 비교에만 쓴다.

**결과**

| 지표 | 변경 전: 전부 렌더 | 변경 후 |
| --- | --- | --- |
| 데이터 수신 (1,000행씩 100회) | 3,160ms | |
| 데이터 수신 후 표시까지 | 8,705ms | |
| 접속부터 표시까지 | 12,391ms | |
| DOM 노드 | 800,086개 | |
| 메모리(JS 힙) | 179MB | |
| 스크롤 프레임 | 6fps | |
| 스크롤 중 가장 긴 프레임 | 233ms | |
| 50ms 넘는 프레임 | 27개 | |

변경 전 3회 범위: 표시까지 8,423~9,182ms, 가장 긴 프레임 217~250ms.

**재현**: 변경 전 코드는 커밋 메시지 "측정 1 변경 전 기준 수치 기록"의 `src/features/messages/plain-recipient-table.tsx`다.

**해석하지 않는 값**: Long Task는 렌더에 약 9초가 걸렸는데도 약 800ms짜리 1건만 잡혔다. React가 렌더를 작게 나눠 실행했기 때문으로 추정하지만 확인하지 못해 표에서 뺐다.
